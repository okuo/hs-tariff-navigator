# TariffScope 改善計画

TariffScopeは、HSコード検索、FTA/EPA比較、削減額シミュレーションを通じて、貿易実務の事前調査を短時間で進めるためのChrome拡張機能です。この文書では、想定課題と対応方針を整理します。

## 解決したい課題

| 課題 | 対応方針 | 状態 |
|------|----------|------|
| 税率データが未収録でも推定値が実データのように見える | 結果、CSV、コピー出力で「収録データ」と「参考推定」を分けて表示する | 初回対応済み |
| EUや個別国コードがUIとデータで一致しない | UIに収録国を追加し、EU選択時は加盟国コードへ展開して照合する | 初回対応済み |
| 収録件数がREADME、manifest、実ファイルでズレる | `data-manifest.json` とドキュメントを実データ件数に合わせる | 初回対応済み |
| アプリの価値がストア説明やREADMEで伝わりにくい | 「何を解決するか」「何には使えないか」を明示する | 初回対応済み |
| オンライン更新元が未設定 | 正式なデータ配信元を設計し、更新日・出典・適用期間を表示する | 表示基盤対応済み |
| テスト実行環境の不整合 | JestのTypeScript変換をローカルトランスフォーマーに切り替え、CIとローカルで再現しやすくする | 初回対応済み |
| 商品説明からHSコード検索語を作る手間が残る | Chrome内蔵AIで商品説明を検索語へ整理し、既存検索へ流す | 初回対応済み |
| 原産地規則が協定単位で粗い | HSコード・品目条件に近い粒度へ拡張する | 未着手 |

## 優先順位

1. **信頼性の表示**: 税率の根拠、推定、未収録を明示する。
2. **国コード整合性**: UIで選べる国と収録データを合わせ、EUを安全に扱う。
3. **説明文の整備**: README、API docs、ストア文案でアプリの解決価値と注意点を書く。
4. **データ更新基盤**: 同梱データからオンライン更新に進める。まず出典・検証日・適用範囲の表示基盤を追加し、正式なオンライン配信元の設定は次段階で進める。
5. **テスト基盤**: 依存バージョンを整え、テストを確実に動かす。
6. **Chrome内蔵AI補助**: 商品説明を検索語に整理し、公式確認前の候補探索を短縮する。
7. **実務精度の向上**: 原産地規則、税率出典、適用期間、品目別条件を拡張する。

## 次に進める改善

1. **オンラインデータ配信元の確定**: `data-manifest.json` の `remote.base_url` に設定できる正式な配信先を用意し、更新チェックから差分反映まで確認する。
2. **テスト基盤の整備**: ローカルJestの初回対応は完了。次は依存のoptional native package不足を `npm ci` で確実に復元できる手順としてREADMEやSETUPへ明記する。
3. **Chrome内蔵AI補助の拡張**: Webページ上の選択テキストから商品情報を要約し、検索欄へ流す。
4. **原産地規則の粒度拡張**: 協定単位の案内から、HSコード・品目条件に近い案内へ広げる。

## ユーザーへの伝え方

TariffScopeは、申告や法的判断を代替するものではありません。強く打ち出す価値は「公式確認前の調査時間を短縮すること」です。

- HSコード候補を素早く探す
- FTA/EPAの見落としを減らす
- 削減額の概算で優先調査対象を決める
- 原産地証明の準備事項を把握する
- 取引情報を外部送信せずローカルで処理する

## 実務上の注意

関税率、原産地規則、協定の適用条件は品目、時期、輸入国、実際の原産性により変わります。TariffScopeの結果は参考情報として扱い、最終判断では税関、通関士、JETRO、各協定文書などの公式情報を確認してください。
